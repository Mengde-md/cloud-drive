# Day04 Final：JVM/IO 文件快照基线

## 当日范围与禁止项

Day04 的唯一增量是把 Day03 中仅存在于 JVM 堆内的 `DriveEntry` 集合保存为文件快照，并在下一次读取时重新构造成合法的目录或文档对象。新增 `EntrySnapshotStore` 与 `SnapshotFormatException`，以及基于临时目录的 IO 测试。实现覆盖读写、缺失文件、格式错误、负大小、嵌套目录创建和临时文件清理。

本日没有 Spring、数据库、线程池、锁、HTTP、缓存或外部中间件。文件快照是单进程、全量替换的最小持久化边界，不提供并发写入控制、版本历史、查询条件或跨进程协调。

## Checkpoint 0 实际起点

Day03 已经能在当前 JVM 中以顺序列表展示条目、以 HashMap 按 ID 索引，并用稳定的相等性处理重复身份。但这些对象只在当前堆中可达：进程结束后，GC 和新的 JVM 启动都不会自动把它们从内存恢复。Day03 的 22 个回归测试是本日唯一输入基线。

## Checkpoint 1 唯一增量

`EntrySnapshotStore` 接收一个快照路径。保存时创建父目录，在同一目录创建临时文件，使用 UTF-8 写出受限行格式，再通过 `ATOMIC_MOVE` 加 `REPLACE_EXISTING` 替换目标；若文件系统不支持原子移动，才退回到普通替换。finally 块删除尚未被移动的临时文件。读取时，文件不存在返回空的不可修改列表；存在时逐行解析类别、ID、拥有者、父级、名称和文档大小，再调用既有的 `DirectoryEntry`、`DocumentEntry` 构造器，使 Day02 的对象不变量继续对恢复路径生效。

名称使用 URL-safe Base64 编码而非直接以分隔符拼接，避免显示名中的分隔符或换行破坏行格式。未知类别、截断字段、无效 Base64、非正 ID、负大小或底层 IO 失败都转为 `SnapshotFormatException`，不会伪装为没有数据。这里的异常只表达文件快照边界，尚未映射 HTTP 状态或写入日志。

## Checkpoint 2 Debug 与边界

测试使用 JUnit `@TempDir`，每个用例拿到独立文件系统位置。往返测试验证父目录可创建、目录与文档按原顺序恢复、中文名称不损坏、文档大小仍正确；缺失文件测试验证空快照不是异常；未知类别、非法编码和负大小分别验证格式失败没有被吞掉；临时文件测试枚举目录，验证成功替换后没有遗留 `.tmp` 文件。

原子替换降低了写新快照时直接覆盖旧目标的风险，却不等于跨进程事务：系统崩溃、文件系统语义、多进程写入和权限控制没有在 Day04 解决。静态范围检查要拒绝 Spring、JPA、JDBC、Redis、线程和锁相关导入；将这些能力提前塞进快照类会破坏 Day05 及以后的学习因果。

## 独立复刻任务

为两种既有领域对象设计一份行格式快照：写入时使用临时文件替换，读取时必须重走对象构造约束。测试至少覆盖正常往返、文件缺失、未知类别、坏编码、非法数值和临时文件清理。完成后解释为什么 HashMap、GC 和文件快照分别解决不同问题，并说明本日为何不能进入并发写入或数据库。
