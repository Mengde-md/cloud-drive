# Day02 Final：网盘条目对象模型

## 当日范围与禁止项

Day02 的唯一增量是把 Day01 的空工程骨架扩展为一组可在内存中创建、遍历和测试的网盘条目对象。新增 `DriveEntry` 接口、`EntryKind` 枚举、抽象基类 `AbstractDriveEntry`、目录和文档两个具体类，以及只使用顺序 `List` 的 `InMemoryEntryList`。主程序只创建一个目录和一个文档，并通过接口类型遍历输出，用于观察多态。

本日明确没有实现 Map/Set 索引、`equals`/`hashCode`、自定义业务异常、文件读写、Spring、数据库、Docker 或 HTTP 接口。`id`、`ownerId`、`parentId` 是内存对象的字段，不代表已经存在主键策略、查询能力或持久化。以顺序列表保存条目是刻意保留的问题现场：按 ID 查询、重复 ID 与业务相等性将由 Day03 解决。

## Checkpoint 0 实际起点

起点是 Day01 已提交的 Maven Java 17 工程。工程已有 `.gitignore`、`pom.xml`、`README.md`、最小启动类与两个 smoke test；此前回归基线可通过 Maven 发现并运行两个测试。起点不含任何领域对象、集合容器、业务服务、异常包或外部依赖。这样 Day02 的每个新增文件都能对应“对象如何表达共同关系与自身约束”这一单一问题。

## Checkpoint 1 唯一增量

共同调用面由 `DriveEntry` 给出：条目标识、拥有者、父级、显示名、类别和改名能力。抽象基类集中执行正数 ID/拥有者/父级约束、非空白名称规范化及受控改名；它将共同读取方法和改名固定为不可重写，避免子类绕过已经验证的规则。`DirectoryEntry` 只表达目录类别；`DocumentEntry` 额外保存不可为负的字节大小。`InMemoryEntryList` 在内部使用 `ArrayList` 保留插入顺序，拒绝 null，并通过 `List.copyOf` 返回不可修改的结构快照，避免外部直接清空内部集合。

封装在这里不是“字段写 private”这么简单。标识、拥有者、父级和大小在构造后不可改；名称只能经 `rename()` 改变，并且复用与构造时相同的规范化规则。接口变量可以同时引用目录与文档，因此调用端不必依赖具体子类。快照只保护列表结构，不构成深拷贝、更不构成鉴权，这一边界已在教材中明确记录。

## Checkpoint 2 Debug 与边界

本日对五个真实、可重复的边界输入做了验证：全空格名称在构造入口抛出 `IllegalArgumentException`；零拥有者被共同构造约束拒绝；负文档大小被文档自身拒绝；向内存列表加入 null 立即抛出 `NullPointerException`；对快照执行 `clear()` 抛出 `UnsupportedOperationException`，且原容器结构未被修改。上述失败均发生在最靠近非法输入的位置，避免了错误对象在后续遍历中才以不明原因失败。

最终执行边界扫描，检查 `java.util.Map`/`Set` 和常见实现类、`equals`/`hashCode` 声明、Spring 与 Java IO/NIO 导入，结果为 `BOUNDARY_SCAN=clean`；`TODO`/`FIXME` 扫描亦为 clean。一次早期扫描曾把 Stream 的 `map()` 误判成 Map，这说明工具规则必须匹配具体类型或导入并人工复核，不能以字符串包含关系替代代码审查。
